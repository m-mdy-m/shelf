# Architecture Decision Records

Use this directory for decisions that would be expensive or confusing to reverse later.

Each ADR should answer:

1. **Context:** What problem or constraint requires a decision?
2. **Options:** What realistic alternatives were considered?
3. **Decision:** What is chosen, and why?
4. **Consequences:** What becomes easier, harder, or constrained?
5. **Status:** Proposed, accepted, superseded, or rejected.

Name files with a stable sequence, for example 0001-desktop-runtime.md. Keep each ADR focused. Update the normative specification when an accepted decision changes product or architecture requirements.
