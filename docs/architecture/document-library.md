# Document library and local import

The local library is coordinated by `DocumentLibraryService` in `@shelf/reader-core`. It depends on narrow source, locator, permission, copy-store, repository, clock, and ID-generation ports. The service contains no picker UI, filesystem API, OS URI, SQL driver, or network dependency.

## Import modes

| Mode | Stored bytes | Locator | Behavior |
|---|---|---|---|
| `imported-copy` | Copied into Shelf-managed storage | Must be reopenable | The original may be transient; the library copy survives after the picker handle closes. |
| `external-reference` | Remains at the original source | Must be reopenable | Opening rechecks permission, availability, and content fingerprint. |

The `DocumentCopyStorePort` receives an open source handle and streams it into app-managed storage. Its implementation must read through `DocumentSourcePort` in chunks no larger than 1 MiB, return a reopenable locator, and remove partial output if copying fails. Platform pickers and URI representations remain in platform adapters.

## Identity, fingerprints, and duplicates

A document ID is generated by Shelf and never derived from a file name, path, URI, or content. A streaming SHA-256 fingerprint is computed from the actual PDF bytes with bounded reads; the full file is not buffered in memory.

By default, importing content with an existing fingerprint returns the existing library record and stable ID. The caller may explicitly choose `keep-both`, which creates a distinct record and exposes the existing ID as `duplicateOf`. A fingerprint is a content-match key, not the primary document identity.

The importer checks both the declared media type and the leading PDF signature. It strips path-like components from display names before constructing a title and never stores the source locator in the exportable `Document` record.

## Open, missing access, and relinking

Opening a library item:
1. Reads its separate opaque locator.
2. Checks source permission and asks the platform port to renew promptable/expired access.
3. Opens the source and recomputes the SHA-256 fingerprint before declaring it available.
4. Returns `document-missing`, `permission-required`, `permission-denied`, `permission-expired`, or `document-changed` distinctly and persists the corresponding `Document.accessState`.

A missing source and an expired permission are not treated as the same condition. If an external file has changed, Shelf keeps the original fingerprint so anchors/annotations are not silently attached to different content.

`relinkDocument` accepts a replacement only when its bytes match the stored fingerprint. A different PDF must be deliberately reimported as a new document; relinking cannot silently replace content identity.

## Failure and rollback behavior

Import validates and fingerprints before writing library records. If a copy or metadata/locator persistence step fails, the service closes the source handle and compensates by deleting the newly written locator and app-managed copy. Duplicate reuse closes the newly opened source without creating another record.

## Platform delivery boundary

The application service is implemented and tested using fake ports. Browser picker/OPFS persistence and native Android Storage Access Framework / iOS security-scoped file adapters are platform implementations of these ports; they must not move OS file handles or URI assumptions into Reader Core. A UI picker and durable repository backend remain separate integration work and are not claimed by this service-only change.
