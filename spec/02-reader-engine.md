# Shelf — Reader engine

## Responsibilities
Own document lifecycle, navigation, rendered page state, selection, reading position, and user-facing annotations. Do not own AI provider calls or external note-export integrations.

## Rendering
- Start with Mozilla PDF.js behind a Shelf adapter; use its worker where supported.
- Render pages on demand and virtualize off-screen pages; never mount every page of a large PDF.
- Support continuous/single-page modes, zoom, fit-width/page, page jump, previous/next, outline/TOC, and document metadata.
- Handle password-protected, malformed, encrypted, and unavailable PDFs explicitly.
- Keep canvas, text, annotation, and interaction layers distinct.
- Test large documents, mixed sizes, rotations, embedded fonts, ligatures, columns, and RTL.

## DocumentSource port
Provide stable document ID, display name/type, read or byte/range access, size/modified metadata where available, permission/reopen behavior, and explicit missing/expired-permission errors. Adapters may use browser file handles, desktop files, Android content URIs, and iOS document-picker/security-scoped access. Reader core must not depend on one URI scheme.

## Library import and access
- Shelf MUST distinguish an imported local copy from an external reference to a user-owned file.
- An imported copy remains readable offline after the original file is moved or deleted. An external reference reopens only while its platform permission and source remain available.
- Stable Document IDs are generated by Shelf and never derived from path, URI, filename, or content fingerprint.
- The opaque source locator is stored outside the exportable Document record. It is not displayed, logged, or exported.
- Duplicate imports are detected using a versioned content fingerprint calculated from bounded reads. A duplicate returns the existing document and does not silently replace its source or create another ID.
- Missing copies, missing original files, denied permissions, and expired permissions produce distinct recoverable states.
- The browser implementation stores local copies, metadata, and external file handles in IndexedDB. Other platform adapters remain separate implementation work.

## Text and selection
- Use PDF text layer where present; never pretend image-only PDFs contain selectable text.
- Preserve spacing, line breaks, paragraph gaps, punctuation, and reading order as far as the source permits.
- Map selections to page rectangles using text geometry.
- Normalize text for AI while retaining exact selection and geometry for persistence.
- Expose document ID, documented page-index convention, selected text, offsets/anchors, and geometry.

## Annotation types
Bookmark = reading location. Highlight = visual text range. Note = user-authored content optionally attached to a passage. Quote = reusable excerpt attributed to document and location. Keep them distinct. AI actions are proposals; show saved only after a confirmed write.

## Resilient anchors
Never rely only on screen pixels. Persist document ID/page, selected and normalized text, offsets or structural anchor, page-relative rectangles, document fingerprint, and anchor schema version. Resolve text anchor first, geometry second. Ambiguous anchors become visibly unresolved, not silently attached elsewhere.

## Progress/search/accessibility
Persist last document, page/scroll, zoom, reading mode, and timestamps; debounce frequent writes. MVP search is local over extractable text with cancellable, bounded indexing. OCR is deferred and image-only documents must explain why selection/search is unavailable. Include keyboard navigation, semantic lang/dir, mixed RTL/LTR tests, screen-reader support, reduced motion, scalable typography, contrast, and mobile touch targets.

## PDF engine implementation boundary

- The PDF engine package owns the locked PDF.js runtime, PDF worker, custom range transport, page renderer, and page virtualizer. Reader Core remains PDF.js-free.
- PDF.js range chunks are capped at the Reader Core 1 MiB source-read limit. Streaming and background auto-fetch are disabled when a document is opened through the source port.
- Worker and document loading tasks are destroyed when a session closes; pending source reads settle before the platform handle is released.
- Page indexes remain zero-based in Shelf and convert to PDF.js's one-based page number only inside the adapter.
- Page windows use measured page geometry plus bounded overscan. The UI mounts only returned page descriptors; it must not render every page in a long PDF.
- Canvas, selectable text, and Shelf annotations are separate layers. PDF.js annotations are disabled in the canvas renderer to avoid mixing vendor-owned and Shelf-owned annotation state.
- Deploy the version-matched worker, CMaps, ICC profiles, standard fonts, and WASM assets from the locked pdfjs-dist dependency on the same origin as the web app.


## Reader navigation and reading state

- The web Reader mounts only the pages returned by the PDF engine's virtual window. Mounted pages are cancelled and removed as they leave the bounded window.
- Navigation uses Shelf's zero-based PageIndex internally and one-based page numbers only in the page input and labels.
- Continuous mode derives the current page from the scroll container and measured page offsets. Single-page mode mounts only the selected page.
- Zoom is bounded between 25% and 400%; Fit Width and Fit Page derive scale from the selected page geometry and the visible reader viewport.
- Outline entries expose safe titles, child items, and resolved zero-based page indexes. External outline URLs and PDF.js objects do not cross the adapter boundary; unresolved destinations remain non-navigable labels.
- The browser stores per-document page, normalized intra-page scroll, zoom, and reading mode in a versioned IndexedDB object store. Writes are debounced, flushed when the document becomes hidden, and attempted again on pagehide after render resources are synchronously disposed.
- The outline is loaded only when the Contents panel is first opened. Destination lookups use bounded concurrency (at most 12 active PDF.js lookups) and preserve source ordering; failed outline loads can be retried.
- Page rendering keeps each mount in a loading state until its render task settles. Failed page renders expose an explicit Retry action and are not retried on every scroll or layout pass.
- Previous/next, page jump, outline activation, and keyboard commands share the same navigation path. Native scrolling and touch panning remain available in continuous mode.


## Text extraction, local search, and precise selection

- `PdfDocumentSession.getPageText(PageIndex, AbortSignal?)` streams PDF.js text content into a Shelf-owned page model; PDF.js proxy objects never leave the adapter.
- A page extraction is bounded to 50,000 text items and 500,000 characters and participates in a 24-page LRU cache. Cancellation cancels the active text stream.
- Extracted text is NFKC-normalized (including compatibility ligatures), and runs preserve UTF-16 start/end offsets, direction, font name, and normalized viewport rectangles. Geometry includes page rotation.
- Layout reconstruction groups nearby baselines, inserts punctuation-aware word spaces, preserves line/paragraph gaps, detects a simple two-column gutter, and uses RTL ordering for RTL lines. These heuristics are tested fallbacks; no semantic reading-order guarantee is made for arbitrary PDFs.
- Local search is sequential, cancellable, and bounded to 2,000 pages, 2,000,000 indexed characters, 100 results, and 20 results per page. Search normalization handles case, NFKC, and whitespace while returning offsets into the extracted page text.
- Browser selection reports exact selected text, DocumentId, zero-based PageIndex, UTF-16 offsets, document fingerprint, anchor version, normalized page rectangles, and offset confidence. Selection offsets are resolved against extracted text, preferring exact text and then the nearest normalized-text occurrence.
- A page with no extractable text is reported as non-selectable. OCR is not run and must never be implied. Search/selection state remains transient; annotation persistence and resilient anchor recovery are handled by Issue #12.

- Extracted pages expose an explicit truncation flag when the 50,000-item or 500,000-character per-page budget is reached; search reports truncated and failed pages so partial results are not presented as complete.
- Search queries are limited to 256 characters; the per-page transient interaction overlay is capped at 500 markers and selection geometry at 512 rectangles.
- The ReaderWorkspace controller and optional selection callback expose transient TextSelection metadata to future annotation/context workflows without writing an Annotation or Quote.


## Bookmarks, annotations, quotes, and anchor recovery

- The Reader exposes distinct page bookmark, passage highlight, passage note, and quote actions. Notes remain user-authored; quotes preserve the selected source excerpt independently.
- A saved state appears only after its repository write succeeds. Failed writes remain errors and never appear in the Saved items list.
- Bookmark, annotation, and quote records use separate IndexedDB object stores keyed by stable record ID and indexed by DocumentId. The upgrade from database version 2 adds these stores without replacing documents, locators, source copies, file references, or reading progress.
- Saved highlights and note markers use the Shelf annotation layer, separate from the PDF canvas, selectable text, and transient search/selection layer. Rendering remains bounded per page by the PDF renderer.
- On reopen, saved anchors first validate their recorded page-local UTF-16 offsets. If those offsets no longer identify the selected text, only one normalized text match may relocate the anchor. Repeated candidates remain unresolved. Saved geometry is a fallback only when the document fingerprint still matches.
- Users can revisit, edit, and delete saved bookmarks, highlights, and notes. Failed writes or deletes do not mutate the in-memory saved list.
